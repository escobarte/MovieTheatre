# Movie_Theatre — техническое задание

Персональный каталог фильмов и сериалов на одного пользователя. Эталонные макеты интерфейса — см. 6.1. Метаданные подтягиваются из TMDB и Кинопоиска **один раз, при добавлении**, дальше запись живёт своей жизнью и правится вручную. Пользователь ставит оценку, статус просмотра, отмечает скачанное, раскладывает файлы по физическим дискам и собирает подборки.

Статус документа: приведён в соответствие с кодом на 2026-11-16. Что из описанного уже сделано и проверено — см. `STATE.md`.

## 0. Правила работы (для Claude Code)

Читается первым и действует на протяжении всего проекта.

**Git не трогать.** Никаких `git add`, `commit`, `push`, `branch`, `merge` и правок в `.git`. Версионирование владелец ведёт вручную сам. Задача — только менять файлы проекта.

**Changelog.** Файл лежит в `docs/CHANGELOG.md`. После каждого выполненного запроса дописывать сверху одну свежую запись: дата, короткое (1–3 строки) описание сделанного, список затронутых файлов. Формат записи:

```
## 2026-07-31
Добавлен экран «Всё кино»: сетка, две строки фильтров, счётчики совпадений.
Файлы: app/vse-kino/page.tsx, components/FilterBar.tsx, lib/filter.ts
```

Ничего не удалять из истории, только добавлять новую запись наверх. Это единственный способ владельцу видеть, что поменялось, раз git ведётся вручную.

**Дизайн — строго по разделу 6.** Никакой самодеятельности в оформлении: цвета, шрифт, скругления, состояния берутся из токенов 6.2 и правил 6.4. При расхождении с макетами верен текст ТЗ. Готовые UI-киты запрещены (см. 6.9).

**Один запрос — один законченный кусок.** Не забегать вперёд по плану без просьбы. Закончил — обновил Changelog — остановился.

## 1. Ключевые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Хостинг | **Vercel** (бесплатный тариф) | Деплой из GitHub по пушу, серверные функции и env из коробки, ноль настройки сервера. Личный сайт на одного человека в лимиты укладывается с запасом. GitHub Pages отпал: там только статика, ключи попали бы в клиент. |
| Фреймворк | **Next.js (App Router) + TypeScript** | Фронт и API-роуты в одном проекте, ключи живут в env на сервере. |
| База | **Turso (SQLite в облаке) + Drizzle ORM** | Бесплатный тариф: 9 ГБ и миллиард чтений в месяц — для личной коллекции неисчерпаемо. Обычный SQLite не подходит: у Vercel файловая система временная, запись пропадёт. Бэкап одной командой. |
| Стили | **Tailwind v4** | Без UI-китов (никаких shadcn/MUI) — они и дают «сгенерированный» вид. |
| Авторизация | **Auth.js (next-auth v5) + вход через Google**, один разрешённый email | Без логина и пароля. Закрыт весь сайт. Подробности — 1.1. |
| Домен | Бесплатный адрес от Vercel: `movie-theatre-eight.vercel.app` | Свой домен не нужен и не покупается. |
| Установка на устройство | **PWA**, только установка | Значок на экране телефона и компьютера. Офлайн-режима нет. См. 1.2. |

### 1.1. Вход

Только через Google, без логина и пароля. Допускается один адрес из `ALLOWED_EMAIL` (сравнение без пробелов по краям и без учёта регистра), и только если Google подтвердил его (`email_verified === true`); любой другой аккаунт получает отказ. Пустой или не заданный `ALLOWED_EMAIL` не пускает никого. Сессия — JWT, без записи в базу. Код — `auth.ts` и `middleware.ts` в корне.

Закрыт **весь сайт, включая чтение и все `/api`**. Неавторизованный запрос страницы перенаправляется на `/vhod` с `callbackUrl` на исходный адрес; неавторизованный запрос `/api/*` получает `401` и `{ "error": "unauthorized" }` без редиректа. Email сессии сверяется с `ALLOWED_EMAIL` на каждом запросе, поэтому смена адреса закрывает и старые сессии. Исключения, которые middleware пропускает: `/api/auth/*`, `/vhod`, `/_next/static`, `/_next/image`, `favicon.ico`, `robots.txt`, манифест `/manifest.webmanifest` и иконки `/icon*`, `/apple-icon*`. Если закрыть манифест и иконки, установка на экран ломается.

Страница входа и страница ошибки — одна, своя: `/vhod`. Отказ Auth.js приводит туда же с `?error=AccessDenied`. Выход — круглая кнопка в шапке на ПК и строка «Выйти» в конце страницы на телефоне (6.7), после выхода — снова `/vhod`.

OAuth-клиент создаётся в Google Cloud Console, приложение в режиме Testing, адрес владельца добавлен в тестовые пользователи. Redirect URI: `https://movie-theatre-eight.vercel.app/api/auth/callback/google`. Адрес фиксирован, поэтому на preview-адресах Vercel вход не работает — проверять нужно на боевом.

**Когда проверка входа выключена.** Ровно в двух случаях: `VERCEL_ENV === 'preview'` (preview-деплои и так закрыты защитой самого Vercel, а вход на них работать не может) и `NODE_ENV === 'development'` (`next dev`). Тогда middleware пропускает всё, `auth()` не вызывается вовсе, кнопки «Выйти» нет. На боевом (`VERCEL_ENV === 'production'`) и в любом непонятном случае — например, `next start` без Vercel — проверка включена.

### 1.2. PWA

Манифест через `app/manifest.ts` (`/manifest.webmanifest`): `name` и `short_name` `Movie_Theatre`, `start_url: "/"`, `display: standalone`, `lang: ru`, цвет фона и темы `#121217`. Иконки: `/icon-192.png` и `/icon-512.png` (`purpose: any`), `/icon-maskable-512.png` (`purpose: maskable`), `apple-touch-icon` 180 (`app/apple-icon.png`), favicon 32 (`app/favicon.ico`). В `<head>` — `theme-color`, `apple-mobile-web-app-capable`, `apple-mobile-web-app-title`. Манифест и иконки отдаются без входа (1.1). Только установка на экран, сервис-воркера с офлайн-кэшем нет: каталог живёт в облачной базе и без сети бесполезен.

**Иконка — вариант «MT и хлопушка».** Сплошной фон `#121217` на весь квадрат, без своих скруглений (их делает система). Слева буквы «MT» — Onest 700, `#F5F5F7`, межбуквенный 0.01em. Справа, вместо «_» логотипа, хлопушка: белая планка с тремя тёмными полосками, повёрнутая на −14°, над красным (`#E5142B`) корпусом; корпус стоит впритык к нижней линии букв. Пропорции группы: квадрат хлопушки 34×34 равен 0.568 размера шрифта букв, низ квадрата ниже базовой линии на 0.031 размера шрифта; зазор от конца строки «MT» до квадрата хлопушки — 0.185 высоты букв (в 512 `any` — 19px), видимый просвет между «T» и хлопушкой ≈ 0.25 высоты букв. Крышка хлопушки ниже верха букв, поэтому по вертикали группа центрируется по буквам. Ширина группы по видимым границам: `any` и apple-icon — 59% стороны (от края не меньше 20%; в 512 буквы ≈102px), `maskable` — 51% (от края не меньше 24%), favicon 32 — ≈70%, хлопушка без полосок (на 32px они сливаются). Группа по центру по видимым границам. Буквы в иконке — кривые из Onest Bold, исходники `assets/pwa/icon.svg`, `icon-maskable.svg`, `favicon.svg`; PNG сгенерированы из них один раз и лежат в репозитории.

## 2. Модель данных

Пять таблиц: `movies`, `lists`, `list_items`, `saved_views`, `disks`. Фильмы и сериалы живут в одной — различаются колонкой `kind`.

### 2.1. `movies`

```ts
{
  id             integer  primary key
  kind           text     not null      // 'movie' | 'tv'

  // --- заполняется из API, но редактируется вручную ---
  tmdbId         integer  unique not null
  imdbId         text
  kpId           integer
  title          text     not null      // русское
  originalTitle  text
  year           integer
  posterUrl      text
  backdropUrl    text
  trailerKey     text                   // идентификатор ролика YouTube
  overview       text
  runtime        integer                // фильм: всего; сериал: минут в серии (если TMDB не отдаёт — длительность последней вышедшей серии)
  seasons        integer                // только kind='tv'
  episodes       integer                // только kind='tv'
  genres         text                   // JSON: string[]
  countries      text                   // JSON: string[]
  director       text                   // сериал: создатель
  producers      text                   // JSON: string[], 1–2 человека
  cast           text                   // JSON: string[], 3–4 человека
  ratingKp       real
  ratingImdb     real
  ratingTmdb     real

  // --- только вручную ---
  status         text     not null      // 'none' | 'watched' | 'planned' | 'watching' | 'skip'
  rewatch        integer  default 0     // «хочу пересмотреть», только при status='watched'
  rating         integer                // 1..10, nullable
  watchedAt      text                   // ISO date, nullable
  progressSeason integer                // только kind='tv'
  progressEpisode integer               // только kind='tv'
  note           text
  tags           text                   // JSON: string[]
  favorite       integer  default 0

  // --- файл ---
  fileStatus     text     default 'none' // 'none' | 'downloading' | 'have' | 'deleted'
  torrentUrl     text                   // ссылка на раздачу
  diskId         integer                // физический диск, ссылка на disks.id; один фильм — один диск
  sizeGb         real                   // вес файла в ГБ, вводится вручную, необязателен
  path           text                   // папка или полный путь на диске
  quality        text                   // '1080p', '2160p', 'BDRemux', ...

  createdAt      text     not null      // дата добавления на сайт
  updatedAt      text
}
```

Названия статусов в интерфейсе: `none` — Не смотрел, `watched` — Смотрел, `planned` — Буду смотреть, `watching` — Смотрю (только сериалы), `skip` — Не стоит смотреть.

**Почему «Хочу пересмотреть» — не статус, а флажок.** Пересмотр по смыслу надстраивается над «Смотрел», а не заменяет его. Отдельной колонкой он позволяет спросить «просмотренное с оценкой 8+, что хочу пересмотреть» — статусом такой вопрос не выражается.

Индексы: `tmdbId` (unique), `kind`, `status`, `year`.

### 2.2. Импорт один раз, дальше только правки

Метаданные запрашиваются у API **однократно, в момент добавления**. Автоматических обновлений в проекте нет: ни фонового сравнения, ни отслеживания того, какие поля правились вручную. После импорта источник истины — база, а не TMDB, и разницы между «автоматическим» и «своим» полем не существует, всё редактируется одинаково.

Единственное исключение — ручное действие «Перезаполнить из API» в карточке, с подтверждением «перезапишет все поля, кроме личных и сведений о файле». Оно нужно на случай, когда в день добавления Кинопоиск был недоступен или упёрся в суточный лимит и запись осталась без оценок КП и IMDb. Само по себе не срабатывает никогда.

Перезаполнение идёт тем же кодом, что добавление (TMDB → Кинопоиск → слияние, с раскладкой сборных жанров сериалов), и перезаписывает только поля из API: `imdbId`, `kpId`, `title`, `originalTitle`, `year`, `posterUrl`, `backdropUrl`, `trailerKey`, `overview`, `runtime`, `seasons`, `episodes`, `genres`, `countries`, `director`, `producers`, `cast`, три рейтинга; ставит `updatedAt`. Не трогает `kind`, `tmdbId`, личные поля, сведения о файле, дату добавления и состав списков. **Сбой Кинопоиска ничего не затирает:** если КП не дал записи (лимит, ошибка, таймаут 8 с, а также «не нашёл» или нет `imdbId`), его поля — `kpId`, `ratingKp`, `ratingImdb` и название — остаются прежними, а не становятся пустыми; постер из КП тоже сохраняется, если у TMDB своего нет. При сбое ответ несёт `kpFailed: true`, и карточка пишет «Обновлено, но Кинопоиск не ответил — оценки КП и IMDb прежние». Если не ответил TMDB — не меняется ничего, «Не удалось обновить».

Следствие: постер хранится ссылкой на CDN TMDB и не обновляется. Если ссылка однажды отвалится, поле постера правится как любое другое — можно вставить свою.

### 2.3. Учёт скачанного

Группа полей, не связанная со статусом просмотра: фильм может быть скачан и не посмотрен, и наоборот.

`fileStatus` — Нет · Качаю · Скачан · Удалён после просмотра. Последнее значение полезнее, чем кажется: оно отличает «никогда не искал» от «был, посмотрел, освободил место».

`torrentUrl` — ссылка на раздачу. Хранится и тогда, когда файл ещё не скачан: один раз нашёл раздачу с нужной озвучкой — больше не ищешь заново.

**Где лежит файл — диск и вес.** Раньше здесь было текстовое «хранилище»; его заменили физическими дисками (2.7). У записи два поля: `diskId` — на каком диске лежит, `sizeGb` — сколько файл весит. По диску работает фильтрация: можно спросить «что лежит на диске F», собираясь в поездку, или «что можно удалить с диска C, когда кончается место». `path` — свободный текст с папкой на диске, справочный, в фильтрах не участвует.

**Один фильм или сериал — один диск.** Раскладывать запись по нескольким дискам не нужно, сериал целиком лежит на одном.

**Откуда берётся вес.** Автоматически его взять негде: сайт не видит файловую систему. Вес вводится вручную в карточке записи при редактировании и необязателен. Остаток места на диске считается из введённых весов, поэтому у диска, где вес указан не у всех, показывается пометка «подсчёт неполный».

`quality` — необязательное, тоже с автодополнением: `1080p`, `2160p`, `BDRemux`.

Ради чего вся группа. Её окупают два запроса: **«буду смотреть» и не скачан** — что надо найти; **«смотрел» и скачан** — что можно удалить, когда кончается место.

### 2.4. `lists` и `list_items` — ручные списки

```ts
lists {
  id           integer  primary key
  title        text     not null
  description  text
  coverMovieId integer                  // постер для обложки
  position     integer                  // порядок списков между собой
  createdAt    text     not null
}

list_items {
  listId    integer  not null
  movieId   integer  not null
  position  integer  not null           // ручной порядок внутри списка
  note      text                        // «почему он здесь»
  primary key (listId, movieId)
}
```

Порядок внутри списка — смысловая часть («Топ-10 всех времён»), поэтому перетаскивание обязательно. Один фильм может состоять в любом числе списков.

### 2.5. `saved_views` — сохранённые фильтры

```ts
saved_views {
  id        integer  primary key
  title     text     not null
  query     text     not null           // строка запроса из адресной строки
  position  integer
}
```

Динамическая подборка: состояние фильтров и так живёт в URL, поэтому сохранённый фильтр — это имя плюс строка запроса. «Непросмотренная советская фантастика» пополняется сама по мере роста коллекции.

### 2.6. Три способа группировки — не путать

| | Теги | Списки | Сохранённые фильтры |
|---|---|---|---|
| Что это | плоские метки | именованная подборка | именованное условие |
| Порядок | нет | ручной | задаётся сортировкой |
| Состав | — | фиксированный | обновляется сам |
| Пример | `нуар`, `тарковский` | «Показать друзьям» | «Не смотрел, СССР, фантастика» |

### 2.7. `disks` — физические диски

```ts
disks {
  id          integer  primary key
  name        text     not null           // короткое имя: «A», «B», «SSD-3»
  sizeGb      integer  not null           // объём диска
  note        text                        // необязательная пометка
  position    integer                     // порядок на экране
}
```

Точный состав колонок смотреть в `lib/db/schema.ts` и `drizzle/0001_disks.sql`; код — источник истины. Сейчас у владельца 15 SSD разных размеров.

**Занято** = сумма `sizeGb` записей на диске. **Свободно** = объём минус занято. Полоса заполнения голубая (`--sky`), при заполнении ≥ 90% — оранжевая (`--orange`); красный не используется (красный — только действия, 6.4). Если у части записей веса нет, диск помечается «подсчёт неполный».

## 3. Источники и слияние

### 3.1. TMDB — основа

- Поиск: `/3/search/multi?query=&language=ru-RU` — возвращает фильмы и сериалы вперемешку с полем `media_type`, поэтому окно добавления одно на оба типа
- Фильм: `/3/movie/{id}?language=ru-RU&append_to_response=credits,videos`
- Сериал: `/3/tv/{id}?language=ru-RU&append_to_response=aggregate_credits,videos`
- Постеры: `https://image.tmdb.org/t/p/w500{poster_path}`, для карточки `w780`

Отличия сериала: режиссёр берётся из `created_by`, состав — из `aggregate_credits.cast`, число сезонов и серий — из `number_of_seasons` и `number_of_episodes`, хронометраж — из `episode_run_time[0]`, а если массив пуст (часто у свежих сериалов) — из `last_episode_to_air.runtime`.

**Трейлер:** из `videos.results` отобрать записи с `site === 'YouTube'` и `type === 'Trailer'`, предпочесть русскую озвучку, при её отсутствии — английскую, сохранить только `key`.

**Продюсеры:** из `credits.crew` отфильтровать `job === 'Producer'` и взять первых двоих по порядку. У крупных фильмов в этой графе бывает 10–15 человек вместе с исполнительными и линейными — тянуть всех нельзя, поле станет нечитаемым. По продюсерам фильтрация не предусмотрена, поле справочное.

### 3.2. Кинопоиск — рейтинги и русские названия

`GET https://api.poiskkino.dev/v1.4/movie?externalId.imdb={imdbId}`, заголовок `X-API-KEY`. Бесплатно ключ выдаёт бот `@poiskkinodev_bot`. Таймаут запроса 8 секунд.

Возвращает объект `rating` с полями `kp`, `imdb` и `tmdb` — **это единственный источник оценки IMDb в проекте**, TMDB собственный рейтинг IMDb не отдаёт. Плюс точное русское название, что критично для советского и старого кино.

Бесплатный токен — 200 запросов в сутки. Запрос выполняется один раз при добавлении, дальше данные лежат в базе. Если лимит исчерпан, сервис недоступен или не ответил за 8 секунд, фильм добавляется без полей КП, а дозаполнить можно позже кнопкой обновления. Рейтинг `0` трактуется как «нет оценки» и сохраняется как `null`.

Запасной вариант для оценки IMDb, если понадобится: OMDb API, 1000 запросов в сутки бесплатно.

### 3.3. Правила слияния

| Поле | Источник |
|---|---|
| Название | `kp.name` → `tmdb.title(ru)` → `tmdb.original_title` |
| Постер | TMDB, при отсутствии — КП |
| `ratingKp`, `ratingImdb` | Кинопоиск |
| `ratingTmdb` | TMDB (`vote_average`) |
| Состав, жанры, трейлер, продюсеры | TMDB |
| Год, хронометраж, описание | TMDB |

Страны: TMDB отдаёт коды ISO, они переводятся в русские названия по `/configuration/countries` плюс небольшая таблица исторических кодов (`SU` → СССР, `XC` → Чехословакия, `XG` → ГДР).

Рейтинги хранятся тремя отдельными числами и не усредняются.

## 4. API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/movies` | Вся коллекция, **облегчённые поля**: id, kind, title, originalTitle, year, posterUrl, runtime, genres, countries, director, три рейтинга, status, rewatch, rating, tags, favorite, createdAt. Плюс `cast`, `episodes`, `seasons`, `diskId`, `sizeGb` и `backdropUrl` — без них не работают поиск по актёрам, подсчёт часов сериалов, фильтр по диску и кадры карусели. | `GET` | `/api/movies/[id]` | Полная карточка. |

| `POST` | `/api/movies` | Тело `{ tmdbId, kind }`. Сервер тянет TMDB → КП, сливает, пишет, возвращает готовую запись. |
| `PATCH` | `/api/movies/[id]` | Любое поле записи. После импорта автополя и личные ничем не отличаются. |
| `POST` | `/api/movies/[id]/refill` | Ручное перезаполнение из API по подтверждению (2.2). Личные поля и сведения о файле не трогает. Сбой КП не затирает прежние поля КП, в ответе `{ movie, kpFailed }`; сбой TMDB — `502`, запись не меняется. |
| `DELETE` | `/api/movies/[id]` | Удаление. |
| `GET POST` | `/api/lists` | Список подборок, создание. |
| `PATCH DELETE` | `/api/lists/[id]` | Переименование, описание, обложка, удаление. |
| `PUT` | `/api/lists/[id]/items` | Полный состав с порядком — одним запросом после перетаскивания. |
| `GET POST DELETE` | `/api/views` | Сохранённые фильтры. |
| `GET POST` | `/api/disks` | Список дисков со сводкой (занято, свободно, число записей), создание. |
| `PATCH DELETE` | `/api/disks/[id]` | Имя, объём, пометка, удаление. |

Весь сайт и все роуты закрыты входом (1.1): без сессии `/api/*` отвечает `401`. Обращения к внешним API — только на сервере.

## 5. Интерфейс

### 5.1. Навигация

Шапка на всех экранах: логотип `MOVIE_THEATRE` слева (клик — на Главную), пять пунктов, справа иконка поиска и красная кнопка «Добавить».

| Пункт | Что показывает | Когда сюда заходят |
|---|---|---|
| **Главная** | Витрина: карусель последних добавленных, полки, подборки | Без конкретной цели — «а что у меня есть» |
| **Всё кино** | Полный каталог со всеми фильтрами и сеткой | С целью найти или сузить |
| **Списки** | Ручные подборки обложками, отдельной группой — сохранённые фильтры | Работа с подборками |
| **Диски** | Физические диски: занято, свободно, что на каждом лежит | «Куда это положить» и «что удалить» |
| **Статистика** | Числа по коллекции | Из любопытства |

**Почему два пункта, а не один «Коллекция».** Разглядывание и поиск — разные задачи с разными интерфейсами. Витрине нужны крупные карточки и полки, каталогу — плотная сетка и панель фильтров. Смешанные в один экран, они мешают друг другу: фильтры оттесняют содержимое вниз, а полки прячут то, что нужно найти.

### 5.2. Главная

Порядок блоков сверху вниз:

1. **Карусель последних добавленных** — три карточки в ряд, у каждой кадр 16:9, дата добавления, название, год, режиссёр, оценка и текущий статус. Листается стрелками, под ней точки. Три — потому что больше не помещается в ряд без измельчения, а вертикальный список тут не нужен.
2. **Граница — строка жанров.** Работает как дверь: клик по жанру уводит на «Всё кино» с уже включённым фильтром. Первая пилюля «Всё кино» активна, пока жанр не выбран, и ведёт в каталог целиком. Над строкой — поясняющая подпись, иначе назначение неочевидно.
3. **Полка «Смотрю сейчас»** — только сериалы с начатым просмотром, прогресс `S2 · E4` прямо на постере. Стоит первой после границы: брошенный на середине сериал иначе теряется в общей сетке и о нём забывают.
4. **Полка «Хочу пересмотреть»** — по флажку `rewatch`.
5. **Полка «Буду смотреть, уже скачано»** — сохранённый фильтр. Самая полезная вечером: это то, что можно включить прямо сейчас.
6. **Полка «Мои списки»** — карточки подборок с числом записей и пометкой «вручную» или «обновляется само».

Пустые полки не отображаются вовсе — заглушек «здесь пока ничего нет» быть не должно, они засоряют витрину.

### 5.3. Всё кино

Заголовок с числом записей, справа переключатель типа: **Всё · Фильмы · Сериалы**.

Ниже две строки фильтров. Первая — жанры пилюлями, самое частое. Вторая — выпадающие: статус, десятилетие, страна, файл, диск, хронометраж. Длинная строка жанров переносится на следующие строки, а не прокручивается. Активный фильтр подсвечивается заливкой.

Под ними полоса результата: «38 из 247», ссылка «Сбросить фильтры» (появляется только когда что-то выбрано), сортировка и выпадающий список минимальной оценки. Рядом — «Сохранить фильтр» и «Выбери за меня».

Дальше сетка постеров: название, год слева, оценка справа.

### 5.4. Как работает фильтрация

При открытии сайта браузер один раз забирает облегчённую коллекцию. Дальше **сервер не участвует**: фильтрация и сортировка идут в памяти через `useMemo`, без запросов и перезагрузок, отклик мгновенный даже при десятке включённых условий.

Логика: внутри категории значения по «или», между категориями по «и». Пример: (драма ИЛИ фантастика) И скачан И оценка ≥ 8.

Категории: тип · статус · «хочу пересмотреть» · личная оценка · рейтинг КП, IMDb или TMDB · десятилетие · жанр · страна · режиссёр · тег · список · хронометраж · избранное · статус файла · диск · качество.

Рядом с каждым значением — счётчик подходящих записей с учётом уже включённых фильтров, чтобы заранее видеть сочетания, дающие ноль.

Сортировки: дата добавления · личная оценка · КП · IMDb · TMDB · год · хронометраж · алфавит · случайно.

Состояние фильтров и сортировки пишется в строку запроса. Отсюда работают кнопка «назад» и закладки, и из этой же строки получается сохранённый фильтр.

«Выбери за меня» предлагает случайную запись из текущей выборки.

### 5.5. Поиск

Открывается оверлеем на весь экран по иконке или клавише `/`.

Ищет по мере ввода в уже загруженной коллекции — то есть мгновенно, без обращения к серверу. Поля: русское название, оригинальное, режиссёр, актёры, теги.

Нормализация запроса: регистр не важен, `ё` приравнивается к `е`, лишние пробелы отбрасываются, совпадение по подстроке в любом месте слова.

Результаты сгруппированы: Фильмы · Сериалы · Списки.

В тот же оверлей ведёт кнопка «Добавить», но открывается он сразу в режиме TMDB (5.8).

### 5.6. Три пустых состояния

Их важно не перепутать — это три разные ситуации с разными действиями.

**Поиск ничего не нашёл.** В личном каталоге это почти всегда значит «такого фильма у меня ещё нет» — то есть ровно тот момент, когда его хочется добавить. Поэтому тупика быть не должно: под сообщением сразу идёт блок «Найти и добавить» с результатами TMDB по тому же запросу и кнопками добавления. Один экран вместо двух. Если и TMDB пуст — сообщение «нигде не нашлось» и подсказка попробовать оригинальное название.

**Фильтры дали ноль.** Другая ошибка и другой текст: «Под выбранные условия ничего не подходит», перечисление активных фильтров и заметная кнопка сброса. Предлагать добавление здесь нельзя — записи есть, просто не подходят.

**Коллекция пуста.** Первый запуск: только приглашение добавить первый фильм, без полок и фильтров.

### 5.7. Карточка

Модальное окно поверх затемнённого экрана — так не теряется позиция прокрутки. Слева постер и кнопка трейлера, справа название, оригинальное название, год, хронометраж, режиссёр, продюсеры, актёры, жанры, страна и три рейтинга рядом одинаковым набором: КП, IMDb, TMDB.

Ниже блок личных полей: статус, флажок пересмотра, оценка, дата просмотра, теги, заметка. Отдельным блоком внизу — файл: статус, ссылка на раздачу, диск, вес файла, путь, качество.

После добавления фильма карточка открывается сразу.

**Два режима.** Каждое открытие карточки и листание ← → — **обычный режим**. Поля, куда вписывается текст или число, показаны простым текстом без рамок в раскладке «подпись — значение», пустое значение — «—» (`--text-3`): название (заголовок 22px 700), оригинальное название (`--text-2`), год, хронометраж (у сериала одной строкой «N сезонов, M серий, ~X мин серия»), режиссёр/создатель, продюсеры, в ролях, жанры, страна (значения через запятую), дата просмотра («20 ноября 2026»), теги, заметка (многострочный текст, переносы сохраняются), раздача (http(s) или magnet — ссылка «Раздача ↗» в новой вкладке, `rel="noopener noreferrer"`; иное — просто текст), вес («11 ГБ»), путь, качество.

**Всегда активны**, без карандаша, и сохраняются сразу: кнопки статуса и «Хочу пересмотреть», кнопки оценки, прогресс сериала (поля «Сезон» и «Серия»), «В список», выпадающие «Статус» файла и «Диск», горячие клавиши 1–0 и W.

Внизу в обычном режиме — только круглая кнопка-карандаш 40px справа (иконка `Pencil` 18px, без фона, рамка 1px `--line-strong`, цвет `--text-2`; наведение — фон `--surface-2`, цвет `--text`; подпись «Редактировать») и подсказка по клавишам на ПК. «Перезаполнить из API» и «Сохранить» не показываются.

**Режим правки** — по карандашу. Все перечисленные текстовые и числовые поля становятся полями `.field`: название, оригинал, год, хронометраж (у сериала — сезоны, серии, минуты), режиссёр, продюсеры, в ролях, жанры, страна, теги — через запятую; дата — `input type=date`; заметка — `textarea`; раздача; вес с «ГБ»; путь; качество. Сохранение автоматическое, по расфокусировке. Внизу: слева «Перезаполнить из API» и статус сохранения, справа подсвеченный карандаш (фон `--surface-3`, иконка `--text`) и «Сохранить» с зазором 8px. В правке ← → не листают, подсказка — «1–0 оценка · W смотрел · Esc готово».

**«Сохранить» не закрывает карточку.** Ждёт все идущие сохранения; при успехе возвращает в обычный режим с новыми значениями, при ошибке остаётся в правке со статусом. Подсвеченный карандаш и Esc в правке (фокус не в поле, выпадающие закрыты) делают то же; Esc из поля только выходит из поля, и оно сохраняется. Закрывают карточку только крестик, клик вне окна, Esc в обычном режиме и «Назад» телефона или браузера; незавершённое поле перед закрытием сохраняется.

**Разбор правки** одинаковый в карточке и на сервере (`PATCH /api/movies/[id]`, `lib/movie-patch.ts`): списки (продюсеры, актёры, жанры, страны, теги) — JSON `string[]` по запятой, trim, без пустых и повторов без учёта регистра, порядок сохраняется, жанры в нижнем регистре; режиссёр — строка «A, B» по тем же правилам; пустой текст — `null`, название пустым не бывает; числа — число ≥ 0 или `null` (год, хронометраж, сезоны, серии, прогресс — целые; вес и рейтинги — до десятых, рейтинги не больше 10; личная оценка — целое 1–10); дата — `ГГГГ-ММ-ДД` или `null`. Неверное значение — ответ 400, запись не меняется. Коллекция в памяти обновляется сразу — фильтры, поиск и статистика видят новые значения.

**Карточка в адресе.** Открытая карточка — параметр `?m=<id>` (остальные параметры, например фильтры «Всё кино», сохраняются); открытие кладёт шаг в историю браузера, «Назад» (в том числе системная на Android и в установленном приложении) закрывает карточку и возвращает прежний адрес и прокрутку. Незавершённое поле при этом сохраняется. Крестик, клик вне окна, Esc и «Сохранить» закрывают через `history.back()`, если карточку открыли этим же переходом, иначе параметр убирается через `replaceState` — пустых шагов в истории не остаётся. ← → меняют `?m=` через `replaceState`. Адрес с `?m=<id>` (ссылка, обновление страницы) открывает карточку сразу — без листания, порядка нет. Оверлей поиска так же: `?search=1` (добавление — `?search=add`), «Назад» закрывает поиск; карточка, открытая из поиска, ложится поверх, и «Назад» из неё возвращает в поиск.

У сериала вместо хронометража — «N сезонов, M серий, ~X мин серия» и прогресс двумя числами.

### 5.8. Добавление

Тот же оверлей, что и поиск, но открытый сразу в режиме TMDB. Кандидаты показываются с типом, годом, оригинальным названием и режиссёром — чтобы не перепутать оригинал с ремейком. Уже добавленные помечены и не дублируются.

### 5.9. Списки

Сетка обложек: название, число записей, пометка происхождения. Внутри списка — обычная сетка плюс перетаскивание для порядка и поле «почему он здесь» у каждой записи.

Сохранённые фильтры показываются там же отдельной группой с пометкой, что состав обновляется сам.

### 5.10. Статистика

Всего записей и часов, раздельно фильмы и сериалы. Распределение личных оценок гистограммой. По десятилетиям. Топ режиссёров, жанров, стран. Сколько скачано и на каких дисках.

Последний бокс страницы — «Резервная копия» с кнопкой «Скачать копию» (9); он остаётся и при пустой коллекции.

Самое интересное — **расхождение с чужими оценками**: в базе лежат три чужих рейтинга, поэтому можно показать записи, которые оценены заметно выше или ниже КП. Больше такого нигде не увидеть, и это единственная метрика здесь, которая говорит о вкусе, а не о количестве.

### 5.11. Клавиатура

Работают все. Только на ПК; молчат, когда фокус в `input`, `textarea`, `select` или `contenteditable`, и при зажатых Ctrl/Cmd/Alt.

- `/` — поиск.
- `Esc` — закрыть верхний открытый слой: выпадающий список → окно «В список» (и подтверждение «Перезаполнить») → карточка → оверлей поиска. Esc работает и из поля ввода; правка в поле перед закрытием сохраняется. Карточка в режиме правки на Esc не закрывается: из поля — выход из поля, вне поля — как «Сохранить», возврат в обычный режим.
- `←` `→` в карточке (только в обычном режиме) — предыдущая / следующая запись в том порядке, в каком записи показаны там, откуда карточку открыли: сетка «Всё кино» с текущими фильтрами и сортировкой, полка, карусель, список, диск, строки расхождения в статистике. Порядок запоминается в момент открытия. На краях ничего не происходит. Перед переходом идущие сохранения дожидаются, как у «Сохранить»; если не сохранилось — карточка остаётся.
- `1`–`9` и `0` в карточке — личная оценка 1–9, `0` = 10, сохраняется сразу.
- `W` в карточке — «Смотрел» ↔ «Не смотрел» (по коду клавиши, работает и в русской раскладке).

Внизу карточки на ПК — строка-подсказка 11px `--text-4`: «← → соседняя · 1–0 оценка · W смотрел · Esc закрыть» (без «← → соседняя», если листать некуда); в режиме правки — «1–0 оценка · W смотрел · Esc готово».

### 5.12. Диски

Сетка дисков: имя, объём, полоса заполнения, «занято из объёма», число записей, пометка «подсчёт неполный». Полоса голубая (`--sky`), при заполнении ≥ 90% — оранжевая (`--orange`); красный не используется. Внутри диска — список записей с весом. Выбор диска и ввод веса — в карточке записи.

### 6.4. Два акцента и правило их разделения

Цветов-акцентов два, и они не пересекаются.

**Красный `--red`** — только действия и активные состояния: кнопка «Добавить», активная пилюля жанра, активный пункт навигации, «Продолжить», «Сбросить фильтры», рамка постера со статусом «Буду смотреть», курсор в поле ввода, активная точка карусели, иконка слева от заголовка полки, залитое сердце избранного.

Невыбранная пилюля жанра, переключатель типа, выпадающий фильтр и пилюля «Ещё N» / «Свернуть» получают рамку `--line-strong` вместо акцентной заливки — рамка нейтральна и в правило двух акцентов не входит. Выбранное состояние у всех них — красная заливка, кроме сортировки: у неё значение есть всегда, поэтому она остаётся в виде «не выбрано».

**Жёлтый `--gold`** — исключительно звезда рейтинга и число рядом с ней. Больше нигде, ни при каких условиях.

Правило проверки простое: если жёлтый появился не вплотную к звезде — это ошибка. Разделение работает потому, что читатель мгновенно закрепляет за жёлтым один смысл, и оценка выхватывается взглядом без подписей.

Красным нельзя набирать абзацы текста и заголовки — только элементы управления и отметки.

Цвета статусов просмотра (`--st-watching`, `--st-watched`, `--st-planned`, `--st-none`) — служебные метки, а не третий акцент: закрашивают только точку 7px перед подписью статуса и полоску прогресса сериала (6.5), сам текст статуса остаётся обычного цвета. Акцентов по-прежнему два — красный и жёлтый.

### 6.5. Компоненты

**Пилюля и фильтр (выбрано/не выбрано).** Общее правило для пилюль жанра (Главная, «Всё кино»), переключателя «Всё · Фильмы · Сериалы», выпадающих фильтров и пилюль «Ещё N» / «Свернуть»: не выбрано — фон прозрачный, рамка `1px solid var(--line-strong)`, текст `--text` 400, счётчик `--text-3`, наведение — фон `--surface-2`; выбрано — фон `--red`, рамка того же цвета, текст белый 500, счётчик и шеврон белые, наведение `--red-hover`. Пилюля жанра и «Ещё N» / «Свернуть»: `padding: 7px 15px`. Выпадающий фильтр: `padding: 7px 14px`, шеврон 13px справа, значение в подписи: `Файл: скачан`. Сортировка — исключение: у неё значение есть всегда, поэтому она всегда в виде «не выбрано», не красная.

**Основная кнопка.** Фон `--red`, белый текст, `padding: 9px 18px`, `--r-pill`, 500. Наведение — `--red-hover`. Вторичная — то же на `--surface-3`.

**Светлая кнопка** — только для кнопки «Трейлер» в карточке записи: фон `--text`, текст и иконка `--bg`, `padding: 9px 18px`, `--r-pill`, 500, иконка `Play`. Наведение — фон `#FFFFFF`. Это не новый акцент, а инверсия нейтральных цветов.

**Заголовок полки.** Иконка, название, счётчик пилюлей (`--surface-2`, `--r-pill`, `padding: 2px 8px`, 11.5px `--text-2`), дальше пустое место на `flex-grow` без фона и без линии — просто раздвигает заголовок и правый край. Цвет иконки у полок Главной: «Смотрю сейчас» — `--st-watching`, «Хочу пересмотреть» — `--violet`, «Буду смотреть, уже скачано» — `--red`, «Мои списки» — `--orange`. У полок («Смотрю сейчас», «Хочу пересмотреть», «Буду смотреть, уже скачано», «Мои списки») справа ссылка «Все →» 12.5px `--text-2` (наведение `--text`); у карусели «Последние добавленные» справа — круглые кнопки-стрелки 32px с рамкой 1px `--line-strong`, иконки в заголовке нет. У шапки сайта разделительной линии нет.

Карточка карусели — рамка 1px `var(--line)`. Панель жанров на Главной — фон `--surface`, рамка 1px `var(--line)`, `--r-lg`, `padding: 20px`, поясняющая подпись внутри панели, над пилюлями.

**Постер.** Соотношение 2:3, `--r-xs`, подложка `--surface-2`. Пока изображения нет — иконка в `--icon-dim` по центру. Под постером название, ниже строка: год слева `--text-3`; оценка справа — то же правило, что в полке и карусели (см. «Подпись у оценки» ниже).

**Подпись у оценки.** Везде, где показана оценка на постере, в полке или в карусели: если есть личная оценка — звезда и число в `--gold`, рядом подпись «моя» 11.5px `--text-3`; иначе если есть оценка КП — звезда и число в `--gold`, рядом подпись «КП»; иначе ничего не показывается. Жёлтый — только у звезды и числа рядом с ней, подпись серая.

**Точка статуса.** Везде, где статус просмотра показан текстом — выпадающий фильтр «Статус» во «Всё кино», кнопки статуса в карточке записи — перед словом идёт точка 7px цвета статуса (`--st-watching`, `--st-watched`, `--st-planned`, `--st-none`). У выбранной (красной) кнопки статуса точка белая, чтобы не терялась на красном фоне. Сам текст статуса цвет не меняет.

**Пометка прогресса на постере.** В левом нижнем углу постера, отступ 6px: фон `--text`, текст `--bg`, 11px, 700, `--r-xs`, `padding: 3px 6px`, формат `S2 · E4`. Показывается у сериалов в полке «Смотрю сейчас» и в сетке «Всё кино», когда известен прогресс.

**Полоска прогресса сериала.** Под постером сериала со статусом «Смотрю» (полка «Смотрю сейчас», сетка «Всё кино») — полоса 3px, `--r-pill`, фон `--surface-3`, заполнение `--st-watching`. Доля — ((сезон − 1) × серий / сезонов + серия) / серий, округляется в границы 0–100%; без известного числа серий или сезонов полоска не показывается.

**Карточка карусели.** Фон `--surface`, рамка 1px `var(--line)`, `--r-md`, `padding: 10px`. Внутри кадр 16:9 с `--r-sm`; в его левом верхнем углу, отступ 10px, — пометка статуса: точка 7px цвета статуса плюс подпись («Смотрю · S1 E3», «Буду смотреть», «Смотрел», «Не смотрел»), фон `rgba(18,18,23,.8)`, `--r-pill`, `padding: 4px 10px`, 11.5px, текст `--text`. Ниже дата добавления служебной подписью, название, метаданные, строка оценки по правилу «Подпись у оценки» выше — статус в этой строке больше не повторяется, он уже на кадре. Карточки в ряду — одной высоты (`align-items: stretch` у ряда, карточка на всю высоту колонкой); строка оценки держит место всегда, даже без оценки, иначе карточка без неё схлопывается ниже соседних.

**Полка на Главной.** Бокс: фон `--panel-sky`, рамка 1px `var(--panel-sky-line)`, `--r-lg`, `padding: 16px 20px 20px`, между боксами 20px. Внутри бокса — заголовок полки, затем горизонтальная прокрутка: ширина постера 104px, зазор `--gap`, правый край намеренно обрезан на половине карточки — подсказка, что прокрутка есть; у ряда обязателен вертикальный `padding`, иначе увеличенный при наведении постер подрежется краем прокрутки.

**Тот же бокс на других страницах.** Фон `--panel-sky` и рамка `--panel-sky-line` используются не только на полках Главной, но и: группы «Списки» и «Сохранённые фильтры» на странице «Списки» (заголовок группы — иконка, название 17px 700, счётчик как у полки; иконка «Списки» — `List` в `--orange`, «Сохранённые фильтры» — `RefreshCw` в `--sky`); каждый раздел статистики на «Статистике»; карточка диска в списке и сводка на странице диска (`/diski/[id]`). Во всех случаях — `--r-lg`, рамка `--panel-sky-line`, между боксами 20px. На Статистике и Дисках `padding` ровный — `20px` со всех сторон (не `16px 20px 20px`, как у полки); панель жанров и карусель этим цветом не окрашиваются, остаются на `--surface`.

**Полоса заполнения диска.** Дорожка `--surface-3`, заполнение `--sky`; при заполнении ≥ 90% заполнение красится в `--orange`. Красный для этой полосы не используется — он занят действиями и выбором (6.4).

### 6.6. Состояния

- **Наведение на постер:** `transform: scale(1.03)`, 150мс, `ease-out`. В полках у контейнера должен быть вертикальный `padding`, иначе увеличенный постер обрежется краем прокрутки.
- **Наведение на кнопку и пилюлю:** смена фона, 120мс.
- **Фокус с клавиатуры:** `outline: 2px solid var(--red); outline-offset: 2px`. Убирать `outline` запрещено, `:focus-visible` обязателен на всех интерактивных элементах.
- `@media (prefers-reduced-motion: reduce)` — все переходы и трансформации отключаются.

### 6.7. Сетка и адаптив

| Ширина | Сетка «Всё кино» | Карусель на Главной |
|---|---|---|
| ≥ 1280px | 6 колонок | 3 карточки |
| 900–1279px | 5 колонок | 3 карточки |
| 600–899px | 3 колонки | 2 карточки |
| < 600px | 2 колонки | 1 карточка, свайп |

Полки прокручиваются горизонтально на всех ширинах. Минимальная поддерживаемая ширина — 360px, горизонтального скролла страницы нет нигде.

На телефоне (< 600px) — логотип, поиск и «Добавить» в первой строке, ряд из пяти разделов всегда виден второй строкой, выход внизу страницы. Ряд — панель `--surface` с рамкой `--line`, `--r-lg`, `padding: 6px`; пункт 56px, иконка над подписью, активный — фон `--red` 14% и иконка `--red`; колонки не уже своей подписи, чтобы «Статистика» 11px влезала на 360px. Выход — строка «Вход: владелец · Выйти» под линией `--line` в конце каждой страницы, кроме `/vhod`; на preview и в dev её нет, на ПК выход в шапке.

### 6.8. Иконки

Только `lucide-react`, `stroke-width: 1.5`, размер 15–20px. Залитые варианты допустимы ровно для двух: звезда рейтинга и сердце избранного. Цвет наследуется от текста, кроме перечисленного в 6.4. Эмодзи не используются.

### 6.9. Прямые запреты

- **Не копировать фирменные элементы стриминговых сервисов** — логотип, шрифт, точный оттенок их красного. Знак у проекта свой: `MOVIE_THEATRE` с подчёркиванием в акценте.
- Градиенты запрещены, с одним исключением: вертикальное затемнение поверх кадра 16:9, чтобы текст поверх него читался. Больше нигде.
- `box-shadow` и `backdrop-filter` не используются; глубина передаётся ступенями `--surface`.
- Жёлтый вне рейтинга, красный в абзацах текста.
- Готовые UI-киты (shadcn, MUI, Chakra) — дают узнаваемый шаблонный вид.
- Анимационные библиотеки; хватает `transition` и `transform`.
- Заглушки в виде цветных прямоугольников: пустой постер — это `--surface-2` с иконкой, а не случайный цвет.
- Пустые полки с текстом «здесь пока ничего нет» — такая полка просто не отображается.

## 9. Бэкапы

- **Кнопка «Скачать копию»** — последний бокс страницы «Статистика»: пояснение, счётчики «N записей · N списков · N фильтров · N дисков», основная кнопка (пока идёт загрузка — «Готовлю…»), под ней дата последней копии с этого устройства (localStorage) или «С этого устройства копий ещё не было». Бокс есть и при пустой коллекции. Кнопка — ссылка на `/api/export` с `download`: файл скачивается, JSON в окне не открывается.
- **`GET /api/export`** — закрыт входом, только чтение (все таблицы одной читающей транзакцией). Файл `movie-theatre-ГГГГ-ММ-ДД.json` (дата по Europe/Bucharest), `Cache-Control: no-store`. Формат: `{ app: "Movie_Theatre", version: 1, exportedAt, schema: "<последняя миграция>", movies, lists, list_items, saved_views, disks }`; строки таблиц как в базе — имена колонок из базы, JSON-поля строками, все колонки без облегчения. Каждая строка таблицы — своей строкой файла. Формат общий для экспорта и восстановления — `lib/backup.ts`.
- **Восстановление** — `npx tsx scripts/restore.ts файл.json`, адрес и токен из окружения или `.env.local`. Проверяет файл (`app`, известная `version`, все пять массивов, значения — строка, число или null), что все пять таблиц в целевой базе есть и **пустые** (иначе «База не пустая. Восстановление делается только в пустую базу.» и выход; флага перезаписи нет), что каждая колонка из файла есть в таблице. Печатает сводку и адрес базы без токена, спрашивает «Восстановить? (да/нет)». Пишет одной транзакцией в порядке disks → movies → lists → list_items → saved_views с исходными id; ошибка — откат всего. Пошагово — `docs/README.md`.
- `turso db shell <имя базы> .dump > backup.sql` — дополнительно, вручную (имя базы — `turso db list`)
- Файл экспорта хранить вне Vercel и Turso — на своём диске или в облаке

Коллекция набирается годами, а бесплатные тарифы приходят и уходят — экспорт должен работать с первого дня.
