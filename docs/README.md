# Movie_Theatre — как всё устроено

Личный каталог фильмов и сериалов на одного человека. Фильм добавляется по названию, сайт сам подтягивает постер, трейлер, режиссёра, актёров и оценки из TMDB и Кинопоиска. Дальше записи правятся только вручную: свой статус, оценка, заметки, списки и на каком диске лежит файл.

**Стек:** Next.js 15 + TypeScript + Tailwind v4 · Turso (SQLite в облаке) + Drizzle · TMDB и Кинопоиск · вход через Google (Auth.js) · Vercel.

**Адрес:** https://movie-theatre-eight.vercel.app

Подробное ТЗ — [`SPEC.md`](SPEC.md), где мы сейчас — [`STATE.md`](STATE.md), история правок — [`CHANGELOG.md`](CHANGELOG.md), правила для Claude Code и дизайн-система — [`CLAUDE.md`](CLAUDE.md).

## Как устроено

- **Vercel** держит сайт и серверные функции. Каждый пуш в GitHub собирается сам: ветка `main` — на боевой адрес, остальные ветки — на свои preview-адреса.
- **Turso** — база. Одна, боевая; всё, что есть в каталоге, живёт там. Структура базы описана миграциями в папке `drizzle/`.
- **TMDB** даёт основу записи: название, год, постер, кадр, трейлер, описание, людей, жанры. **Кинопоиск** (через poiskkino.dev) — русское название и оценки КП и IMDb. Оба опрашиваются только с сервера и только один раз — при добавлении (или по кнопке «Перезаполнить из API»).
- **Вход через Google.** Пускает ровно один адрес — из `ALLOWED_EMAIL`. Без входа закрыт весь сайт, включая API.

### Где что лежит

```
app/            страницы сайта и API (app/api/...)
  api/export    «Скачать копию»: вся база одним JSON
components/     части интерфейса: карточка, поиск, шапка, полки
lib/            работа с TMDB и Кинопоиском, фильтры, статистика,
                lib/db — схема базы и подключение
drizzle/        миграции базы (SQL), применяются по порядку
scripts/        restore.ts — восстановление базы из копии
public/, app/   иконки приложения (PWA)
assets/         макеты интерфейса, только для справки
docs/           документация, в том числе этот файл
```

## Переменные окружения

| Переменная | Для чего |
|---|---|
| `TMDB_API_KEY` | TMDB. Нужен длинный токен (API Read Access Token) — с коротким ключом поиск отвечает 401 |
| `KINOPOISK_TOKEN` | Кинопоиск через poiskkino.dev |
| `TURSO_DATABASE_URL` | Адрес базы Turso (`libsql://…`) |
| `TURSO_AUTH_TOKEN` | Токен доступа к базе |
| `AUTH_SECRET` | Подпись сессии входа (любая длинная случайная строка) |
| `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET` | OAuth-клиент Google |
| `ALLOWED_EMAIL` | Единственный адрес, которому разрешён вход |

Где задавать:

- **На сайте** — Vercel → проект → Settings → Environment Variables, для Production и Preview. После изменения переменных нужен Redeploy: старая сборка их не увидит.
- **Локально** — файл `.env.local` в корне проекта (образец с именами — `.env.example`). Этот файл в git не попадает и никуда не копируется.

## Как идёт разработка

1. Для каждой правки или этапа заводится своя ветка (`phase_8`, `fix/card-edit-2`…).
2. После пуша ветки Vercel собирает её на отдельный preview-адрес. Там и проверяется результат. Preview закрыт защитой самого Vercel, вход через Google там выключен — он и не может работать (см. ниже).
3. Если всё хорошо, владелец сам сливает ветку в `main`. Vercel пересобирает боевой сайт.

**Вход через Google работает только на боевом адресе** `movie-theatre-eight.vercel.app`: в настройках Google прописан один redirect URI, боевой. Локально (`npm run dev`) вход тоже выключен.

Локальный запуск, если нужен: `npm install`, затем `npm run dev` и http://localhost:3000. Учтите: с ключами из `.env.local` локальный сайт работает с той же боевой базой.

## Резервные копии

Коллекция набирается годами, а бесплатные тарифы приходят и уходят. Поэтому **раз в месяц**:

1. **«Скачать копию»** — кнопка внизу страницы «Статистика». Скачивается файл `movie-theatre-ГГГГ-ММ-ДД.json`: вся база — записи, списки, сохранённые фильтры, диски. Под кнопкой видно, когда копию последний раз скачивали с этого устройства.
2. **Дополнительно, по желанию** — полный SQL-слепок средствами Turso (нужен [Turso CLI](https://docs.turso.tech/cli/installation) и `turso auth login`):

   ```
   turso db shell <имя базы> .dump > backup.sql
   ```

   Имя базы показывает `turso db list` (сейчас — `movie-theatre`).

**Где хранить:** вне Vercel и Turso — на своём диске и/или в своём облаке (Google Drive и т. п.). Лучше в двух местах. Старые копии можно не удалять: они маленькие.

## Восстановление из копии

Скрипт пишет **только в пустую базу**. В существующую базу с данными он ничего не запишет — откажет и выйдет. Так задумано: случайно затереть каталог им нельзя.

1. **Создать новую пустую базу в Turso:**

   ```
   turso db create movie-theatre-new
   turso db show movie-theatre-new --url        # адрес libsql://…
   turso db tokens create movie-theatre-new     # токен
   ```

2. **Прописать её адрес и токен в `.env.local`** — `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN`. Прежние значения сохраните отдельно, если старая база ещё жива.
3. **Применить миграции из `drizzle/`** — создать таблицы:

   ```
   npm install
   npm run db:migrate
   ```

   Миграции берут адрес из `.env.local`, поэтому шаг 2 идёт раньше.
4. **Залить копию:**

   ```
   npx tsx scripts/restore.ts путь/к/movie-theatre-ГГГГ-ММ-ДД.json
   ```

   Скрипт проверит файл, убедится, что база пустая, покажет, что и куда запишет (адрес базы без токена), и спросит «Восстановить? (да/нет)». Всё пишется одной транзакцией с прежними id: если что-то пошло не так, база остаётся пустой. В конце — итог по таблицам. Если `npx` спросит, ставить ли `tsx`, — ответить «y».
5. **Поменять переменные в Vercel** — `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN` на новые (Settings → Environment Variables, Production и Preview).
6. **Redeploy** — Vercel → Deployments → последний боевой деплой → ⋯ → Redeploy. Открыть сайт и убедиться, что всё на месте.

Если под рукой только `backup.sql`, его можно залить в новую пустую базу (без шага 3 — в слепке уже есть таблицы): `turso db shell movie-theatre-new < backup.sql`.

## Что делать, если…

**Вход не работает.**
- В Google Cloud Console → APIs & Services → Credentials → OAuth-клиент: в Authorized redirect URIs должно быть ровно `https://movie-theatre-eight.vercel.app/api/auth/callback/google`.
- `ALLOWED_EMAIL` в Vercel совпадает с адресом Google-аккаунта, которым входите.
- Приложение в Google в режиме Testing — адрес должен быть в списке тестовых пользователей (OAuth consent screen → Test users).
- Проверьте, что заданы `AUTH_SECRET`, `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`, и после любых правок переменных сделайте Redeploy.
- На preview-адресах вход не работает в принципе — проверять на боевом.

**Поиск TMDB отвечает 401.** В `TMDB_API_KEY` стоит короткий ключ. Нужен длинный токен: themoviedb.org → Settings → API → «API Read Access Token». Заменить в Vercel и Redeploy.

**Кинопоиск не отдал оценки.** У бесплатного токена poiskkino.dev лимит — 200 запросов в сутки. Запись всё равно добавляется, просто без оценок КП. На следующий день открыть карточку → карандаш → «Перезаполнить из API». Личные поля и сведения о файле эта кнопка не трогает.

**Сборка на Vercel упала на шрифте** (ошибка про `next/font` / Onest / fonts.googleapis.com). Это разовый сбой сети при скачивании шрифта. Vercel → Deployments → упавший деплой → ⋯ → Redeploy.
