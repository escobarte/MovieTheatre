# Movie_Theatre — техническое задание

Персональный каталог фильмов и сериалов на одного пользователя. Эталонные макеты интерфейса — см. 6.1. Метаданные подтягиваются из TMDB и Кинопоиска **один раз, при добавлении**, дальше запись живёт своей жизнью и правится вручную. Пользователь ставит оценку, статус просмотра, отмечает скачанное и собирает подборки.

---

## 1. Ключевые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Хостинг | **Vercel** | GitHub Pages отпадает: там только статика, а ключи TMDB/КП нельзя класть в клиентский бандл. Приватный репозиторий с Pages требует платный тариф. Vercel даёт серверные функции бесплатно, репозиторий на GitHub остаётся приватным. |
| Фреймворк | **Next.js (App Router) + TypeScript** | Фронт и API-роуты в одном проекте, ключи живут в env на сервере. |
| База | **Turso (libSQL/SQLite) + Drizzle ORM** | Бесплатный тариф: 100 БД, 5 ГБ, 500 млн чтений в месяц — на порядки больше, чем нужно. Синтаксис SQLite, бэкап одной командой. |
| Стили | **Tailwind v4** | Без UI-китов (никаких shadcn/MUI) — они и дают «сгенерированный» вид. |
| Авторизация | Один пароль в env → подписанная httpOnly-cookie | Чтение открыто, запись требует cookie. Никаких Auth.js и провайдеров. |

**Явно НЕ используем:** ORM-хэви решения, Redux/Zustand (хватит URL-состояния и `useMemo`), библиотеки UI-компонентов, анимационные библиотеки.

## 2. Модель данных

Четыре таблицы. Фильмы и сериалы живут в одной — различаются колонкой `kind`.

### 2.1. `movies`

```ts
{
  id             integer  primary key
  kind           text     not null      // 'movie' | 'tv'

  // --- заполняется из API, но редактируется вручную ---
  tmdbId         integer  unique not null
  imdbId         text
  kpId           integer
  title          text     not null      // русское
  originalTitle  text
  year           integer
  posterUrl      text
  backdropUrl    text
  trailerKey     text                   // идентификатор ролика YouTube
  overview       text
  runtime        integer                // фильм: всего; сериал: минут в серии
  seasons        integer                // только kind='tv'
  episodes       integer                // только kind='tv'
  genres         text                   // JSON: string[]
  countries      text                   // JSON: string[]
  director       text                   // сериал: создатель
  producers      text                   // JSON: string[], 1–2 человека
  cast           text                   // JSON: string[], 3–4 человека
  ratingKp       real
  ratingImdb     real
  ratingTmdb     real

  // --- только вручную ---
  status         text     not null      // 'none' | 'watched' | 'planned' | 'watching' | 'skip'
  rewatch        integer  default 0     // «хочу пересмотреть», только при status='watched'
  rating         integer                // 1..10, nullable
  watchedAt      text                   // ISO date, nullable
  progressSeason integer                // только kind='tv'
  progressEpisode integer               // только kind='tv'
  note           text
  tags           text                   // JSON: string[]
  favorite       integer  default 0

  // --- файл ---
  fileStatus     text     default 'none' // 'none' | 'downloading' | 'have' | 'deleted'
  torrentUrl     text                   // ссылка на раздачу
  storage        text                   // короткое имя хранилища
  path           text                   // папка или полный путь
  quality        text                   // '1080p', '2160p', 'BDRemux', ...

  createdAt      text     not null      // дата добавления на сайт
  updatedAt      text
}
```

Названия статусов в интерфейсе: `none` — Не смотрел, `watched` — Смотрел, `planned` — Буду смотреть, `watching` — Смотрю (только сериалы), `skip` — Не стоит смотреть.

**Почему «Хочу пересмотреть» — не статус, а флажок.** Пересмотр по смыслу надстраивается над «Смотрел», а не заменяет его. Отдельной колонкой он позволяет спросить «просмотренное с оценкой 8+, что хочу пересмотреть» — статусом такой вопрос не выражается.

Индексы: `tmdbId` (unique), `kind`, `status`, `year`.

### 2.2. Импорт один раз, дальше только правки

Метаданные запрашиваются у API **однократно, в момент добавления**. Автоматических обновлений в проекте нет: ни фонового сравнения, ни отслеживания того, какие поля правились вручную. После импорта источник истины — база, а не TMDB, и разницы между «автоматическим» и «своим» полем не существует, всё редактируется одинаково.

Единственное исключение — ручное действие «Перезаполнить из API» в карточке, с подтверждением «перезапишет все поля, кроме личных и сведений о файле». Оно нужно на случай, когда в день добавления Кинопоиск был недоступен или упёрся в суточный лимит и запись осталась без оценок КП и IMDb. Само по себе не срабатывает никогда.

Следствие: постер хранится ссылкой на CDN TMDB и не обновляется. Если ссылка однажды отвалится, поле постера правится как любое другое — можно вставить свою.

### 2.3. Учёт скачанного

Группа полей, не связанная со статусом просмотра: фильм может быть скачан и не посмотрен, и наоборот.

`fileStatus` — Нет · Качаю · Скачан · Удалён после просмотра. Последнее значение полезнее, чем кажется: оно отличает «никогда не искал» от «был, посмотрел, освободил место».

`torrentUrl` — ссылка на раздачу. Хранится и тогда, когда файл ещё не скачан: один раз нашёл раздачу с нужной озвучкой — больше не ищешь заново.

**Где лежит файл — два поля, а не одно.** `storage` это короткое имя хранилища с автодополнением из ранее введённых значений, ровно как теги: `NAS`, `внешний HDD`, `ноутбук`. По нему работает фильтрация, и это главное — можно спросить «что лежит на внешнем диске», собираясь в поездку. `path` — свободный текст с папкой или полным путём, справочный, в фильтрах не участвует.

Одним полем это делать не стоит: свободный текст не фильтруется, а жёсткий справочник хранилищ потребовал бы экрана настроек ради трёх значений.

`quality` — необязательное, тоже с автодополнением: `1080p`, `2160p`, `BDRemux`.

Ради чего вся группа. Её окупают два запроса: **«буду смотреть» и не скачан** — что надо найти; **«смотрел» и скачан** — что можно удалить, когда кончается место.

### 2.4. `lists` и `list_items` — ручные списки

```ts
lists {
  id           integer  primary key
  title        text     not null
  description  text
  coverMovieId integer                  // постер для обложки
  position     integer                  // порядок списков между собой
  createdAt    text     not null
}

list_items {
  listId    integer  not null
  movieId   integer  not null
  position  integer  not null           // ручной порядок внутри списка
  note      text                        // «почему он здесь»
  primary key (listId, movieId)
}
```

Порядок внутри списка — смысловая часть («Топ-10 всех времён»), поэтому перетаскивание обязательно. Один фильм может состоять в любом числе списков.

### 2.5. `saved_views` — сохранённые фильтры

```ts
saved_views {
  id        integer  primary key
  title     text     not null
  query     text     not null           // строка запроса из адресной строки
  position  integer
}
```

Динамическая подборка: состояние фильтров и так живёт в URL, поэтому сохранённый фильтр — это имя плюс строка запроса. «Непросмотренная советская фантастика» пополняется сама по мере роста коллекции.

### 2.6. Три способа группировки — не путать

| | Теги | Списки | Сохранённые фильтры |
|---|---|---|---|
| Что это | плоские метки | именованная подборка | именованное условие |
| Порядок | нет | ручной | задаётся сортировкой |
| Состав | — | фиксированный | обновляется сам |
| Пример | `нуар`, `тарковский` | «Показать друзьям» | «Не смотрел, СССР, фантастика» |

## 3. Источники и слияние

### 3.1. TMDB — основа

- Поиск: `/3/search/multi?query=&language=ru-RU` — возвращает фильмы и сериалы вперемешку с полем `media_type`, поэтому окно добавления одно на оба типа
- Фильм: `/3/movie/{id}?language=ru-RU&append_to_response=credits,videos`
- Сериал: `/3/tv/{id}?language=ru-RU&append_to_response=aggregate_credits,videos`
- Постеры: `https://image.tmdb.org/t/p/w500{poster_path}`, для карточки `w780`

Отличия сериала: режиссёр берётся из `created_by`, состав — из `aggregate_credits.cast`, число сезонов и серий — из `number_of_seasons` и `number_of_episodes`, хронометраж — из `episode_run_time[0]`.

**Трейлер:** из `videos.results` отобрать записи с `site === 'YouTube'` и `type === 'Trailer'`, предпочесть русскую озвучку, при её отсутствии — английскую, сохранить только `key`.

**Продюсеры:** из `credits.crew` отфильтровать `job === 'Producer'` и взять первых двоих по порядку. У крупных фильмов в этой графе бывает 10–15 человек вместе с исполнительными и линейными — тянуть всех нельзя, поле станет нечитаемым. По продюсерам фильтрация не предусмотрена, поле справочное.

### 3.2. Кинопоиск — рейтинги и русские названия

`GET /v1.4/movie?externalId.imdb={imdbId}`

Возвращает объект `rating` с полями `kp`, `imdb` и `tmdb` — **это единственный источник оценки IMDb в проекте**, TMDB собственный рейтинг IMDb не отдаёт. Плюс точное русское название, что критично для советского и старого кино.

Бесплатный токен — 200 запросов в сутки. Запрос выполняется один раз при добавлении, дальше данные лежат в базе. Если лимит исчерпан или сервис недоступен, фильм добавляется без полей КП, а дозаполнить можно позже кнопкой обновления.

Запасной вариант для оценки IMDb, если понадобится: OMDb API, 1000 запросов в сутки бесплатно.

### 3.3. Правила слияния

| Поле | Источник |
|---|---|
| Название | `kp.name` → `tmdb.title(ru)` → `tmdb.original_title` |
| Постер | TMDB, при отсутствии — КП |
| `ratingKp`, `ratingImdb` | Кинопоиск |
| `ratingTmdb` | TMDB (`vote_average`) |
| Состав, жанры, трейлер, продюсеры | TMDB |
| Год, хронометраж, описание | TMDB |

Рейтинги хранятся тремя отдельными числами и не усредняются.

## 4. API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/movies` | Вся коллекция, **облегчённые поля**: id, kind, title, originalTitle, year, posterUrl, runtime, genres, countries, director, три рейтинга, status, rewatch, rating, tags, favorite, createdAt. Без `overview`, `cast`, `producers`, `note`, `backdropUrl`. |
| `GET` | `/api/movies/[id]` | Полная карточка. |
| `GET` | `/api/search?q=` | Проксирует `/search/multi`, отдаёт до 8 кандидатов с типом, годом, мини-постером и режиссёром. |
| `POST` | `/api/movies` | Тело `{ tmdbId, kind }`. Сервер тянет TMDB → КП, сливает, пишет, возвращает готовую запись. |
| `PATCH` | `/api/movies/[id]` | Любое поле записи. После импорта автополя и личные ничем не отличаются. |
| `POST` | `/api/movies/[id]/refill` | Ручное перезаполнение из API по подтверждению. Личные поля и сведения о файле не трогает. |
| `DELETE` | `/api/movies/[id]` | Удаление. |
| `GET POST` | `/api/lists` | Список подборок, создание. |
| `PATCH DELETE` | `/api/lists/[id]` | Переименование, описание, обложка, удаление. |
| `PUT` | `/api/lists/[id]/items` | Полный состав с порядком — одним запросом после перетаскивания. |
| `GET POST DELETE` | `/api/views` | Сохранённые фильтры. |
| `GET` | `/api/export` | Вся база одним JSON-файлом. |

Разделение `GET /api/movies` на облегчённый и полный варианты — принципиальный момент: при 2000 записей полная выдача весила бы несколько мегабайт, облегчённая укладывается примерно в 200 КБ и грузится один раз за сессию.

Мутирующие роуты проверяют cookie. Обращения к внешним API — только на сервере.

## 5. Интерфейс

### 5.1. Навигация

Шапка на всех экранах: логотип `MOVIE_THEATRE` слева (клик — на Главную), четыре пункта, справа иконка поиска и красная кнопка «Добавить».

| Пункт | Что показывает | Когда сюда заходят |
|---|---|---|
| **Главная** | Витрина: карусель последних добавленных, полки, подборки | Без конкретной цели — «а что у меня есть» |
| **Всё кино** | Полный каталог со всеми фильтрами и сеткой | С целью найти или сузить |
| **Списки** | Ручные подборки обложками, отдельной группой — сохранённые фильтры | Работа с подборками |
| **Статистика** | Числа по коллекции | Из любопытства |

**Почему два пункта, а не один «Коллекция».** Разглядывание и поиск — разные задачи с разными интерфейсами. Витрине нужны крупные карточки и полки, каталогу — плотная сетка и панель фильтров. Смешанные в один экран, они мешают друг другу: фильтры оттесняют содержимое вниз, а полки прячут то, что нужно найти.

### 5.2. Главная

Порядок блоков сверху вниз:

1. **Карусель последних добавленных** — три карточки в ряд, у каждой кадр 16:9, дата добавления, название, год, режиссёр, оценка и текущий статус. Листается стрелками, под ней точки. Три — потому что больше не помещается в ряд без измельчения, а вертикальный список тут не нужен.
2. **Граница — строка жанров.** Работает как дверь: клик по жанру уводит на «Всё кино» с уже включённым фильтром. Первая пилюля «Всё кино» активна, пока жанр не выбран, и ведёт в каталог целиком. Над строкой — поясняющая подпись, иначе назначение неочевидно.
3. **Полка «Смотрю сейчас»** — только сериалы с начатым просмотром, прогресс `S2 · E4` прямо на постере. Стоит первой после границы: брошенный на середине сериал иначе теряется в общей сетке и о нём забывают.
4. **Полка «Хочу пересмотреть»** — по флажку `rewatch`.
5. **Полка «Буду смотреть, уже скачано»** — сохранённый фильтр. Самая полезная вечером: это то, что можно включить прямо сейчас.
6. **Полка «Мои списки»** — карточки подборок с числом записей и пометкой «вручную» или «обновляется само».

Пустые полки не отображаются вовсе — заглушек «здесь пока ничего нет» быть не должно, они засоряют витрину.

### 5.3. Всё кино

Заголовок с числом записей, справа переключатель типа: **Всё · Фильмы · Сериалы**.

Ниже две строки фильтров. Первая — жанры пилюлями, самое частое. Вторая — выпадающие: статус, десятилетие, страна, файл, хранилище, хронометраж. Активный фильтр подсвечивается заливкой.

Под ними полоса результата: «38 из 247», ссылка «Сбросить фильтры» (появляется только когда что-то выбрано), сортировка и ползунок минимальной оценки.

Дальше сетка постеров: название, год слева, оценка справа.

### 5.4. Как работает фильтрация

При открытии сайта браузер один раз забирает облегчённую коллекцию. Дальше **сервер не участвует**: фильтрация и сортировка идут в памяти через `useMemo`, без запросов и перезагрузок, отклик мгновенный даже при десятке включённых условий.

Логика: внутри категории значения по «или», между категориями по «и». Пример: (драма ИЛИ фантастика) И скачан И оценка ≥ 8.

Категории: тип · статус · «хочу пересмотреть» · личная оценка · рейтинг КП, IMDb или TMDB · десятилетие · жанр · страна · режиссёр · тег · список · хронометраж · избранное · год добавления · статус файла · хранилище · качество.

Рядом с каждым значением — счётчик подходящих записей с учётом уже включённых фильтров, чтобы заранее видеть сочетания, дающие ноль.

Сортировки: дата добавления · личная оценка · КП · IMDb · TMDB · год · хронометраж · алфавит · случайно.

Состояние фильтров и сортировки пишется в строку запроса. Отсюда работают кнопка «назад» и закладки, и из этой же строки получается сохранённый фильтр.

### 5.5. Поиск

Открывается оверлеем на весь экран по иконке или клавише `/`.

Ищет по мере ввода в уже загруженной коллекции — то есть мгновенно, без обращения к серверу. Поля: русское название, оригинальное, режиссёр, актёры, теги.

Нормализация запроса: регистр не важен, `ё` приравнивается к `е`, лишние пробелы отбрасываются, совпадение по подстроке в любом месте слова.

Результаты сгруппированы: Фильмы · Сериалы · Списки.

### 5.6. Три пустых состояния

Их важно не перепутать — это три разные ситуации с разными действиями.

**Поиск ничего не нашёл.** В личном каталоге это почти всегда значит «такого фильма у меня ещё нет» — то есть ровно тот момент, когда его хочется добавить. Поэтому тупика быть не должно: под сообщением сразу идёт блок «Найти и добавить» с результатами TMDB по тому же запросу и кнопками добавления. Один экран вместо двух. Если и TMDB пуст — сообщение «нигде не нашлось» и подсказка попробовать оригинальное название.

**Фильтры дали ноль.** Другая ошибка и другой текст: «Под выбранные условия ничего не подходит», перечисление активных фильтров и заметная кнопка сброса. Предлагать добавление здесь нельзя — записи есть, просто не подходят.

**Коллекция пуста.** Первый запуск: только приглашение добавить первый фильм, без полок и фильтров.

### 5.7. Карточка

Модальное окно поверх затемнённого экрана — так не теряется позиция прокрутки. Слева постер и кнопка трейлера, справа название, оригинальное название, год, хронометраж, режиссёр, продюсеры, актёры, жанры, страна и три рейтинга рядом одинаковым набором: КП, IMDb, TMDB.

Ниже блок личных полей: статус, флажок пересмотра, оценка, дата просмотра, теги, заметка. Отдельным блоком внизу — файл: статус, ссылка на раздачу, хранилище, путь, качество.

Любое поле правится по клику. Сохранение автоматическое, по расфокусировке.

У сериала вместо хронометража — «N сезонов, M серий, ~X мин серия» и прогресс двумя числами.

### 5.8. Добавление

Тот же оверлей, что и поиск, но открытый сразу в режиме TMDB. Кандидаты показываются с типом, годом, оригинальным названием и режиссёром — чтобы не перепутать оригинал с ремейком. Уже добавленные помечены и не дублируются.

### 5.9. Списки

Сетка обложек: название, число записей, пометка происхождения. Внутри списка — обычная сетка плюс перетаскивание для порядка и поле «почему он здесь» у каждой записи.

Сохранённые фильтры показываются там же отдельной группой с пометкой, что состав обновляется сам.

### 5.10. Статистика

Всего записей и часов, раздельно фильмы и сериалы. Распределение личных оценок гистограммой. По десятилетиям. Топ режиссёров, жанров, стран. Сколько скачано и по каким хранилищам.

Самое интересное — **расхождение с чужими оценками**: в базе лежат три чужих рейтинга, поэтому можно показать записи, которые оценены заметно выше или ниже КП. Больше такого нигде не увидеть, и это единственная метрика здесь, которая говорит о вкусе, а не о количестве.

### 5.11. Клавиатура

`/` — поиск, `Esc` — закрыть, `←` `→` — соседняя запись в карточке, `1`–`9` и `0` — быстрая оценка, `W` — переключить «Смотрел».

## 6. Дизайн-система

Тема одна, тёмная, переключателя нет. Стилистика — современный стриминговый каталог: почти чёрный фон, красный акцент на действиях, крупные постеры, скруглённые пилюли.

### 6.1. Эталонные макеты

Три статических HTML-файла лежат рядом с проектом и открываются в браузере:

```
B:\MovieTheatre\assets\movie_theatre_home_hero_carousel.html   — Главная
B:\MovieTheatre\assets\movie_theatre_all_films_catalogue.html  — Всё кино
B:\MovieTheatre\assets\movie_theatre_search_empty_state.html   — Поиск и пустой результат
```

**При расхождении макета и текста ТЗ верен текст.** Макеты рисовались раньше и содержат упрощения: вместо постеров и кадров — серые подложки с иконкой, часть блоков показана в одном состоянии из нескольких. Брать из них следует пропорции, плотность, порядок блоков и ощущение — а значения цветов и размеров сверять с токенами ниже.

### 6.2. Токены

Положить в `globals.css`, использовать только через переменные.

```css
:root {
  --bg:         #0B0B0D;   /* фон страницы */
  --surface:    #16161A;   /* панели, карточки, поле поиска */
  --surface-2:  #1E1E23;   /* подложка постера, разделители */
  --surface-3:  #26262C;   /* вторичная кнопка, дорожка ползунка */
  --line:       #1E1E23;

  --text:       #F5F5F7;
  --text-2:     #A1A1AA;
  --text-3:     #6B6B73;
  --text-4:     #5E5E67;
  --icon-dim:   #34343C;   /* иконка внутри пустого постера */

  --red:        #E5142B;
  --red-hover:  #FF2740;
  --gold:       #F5B01A;

  --r-pill: 999px;
  --r-lg:    12px;   /* оверлей, крупные блоки */
  --r-md:    10px;   /* карточка карусели, поле поиска */
  --r-sm:     8px;   /* кадр 16:9, карточка списка */
  --r-xs:     6px;   /* постер */

  --gap: 12px;
}
```

### 6.3. Типографика

Один шрифт — **Onest**, начертания 400, 500 и 700. Подключать через `next/font/google` с `subsets: ['cyrillic', 'latin']`. Второго шрифта в системе нет.

| Роль | Размер | Начертание | Прочее |
|---|---|---|---|
| Логотип | 15px | 700 | `letter-spacing: .1em`, верхний регистр, подчёркивание в `--red` |
| Заголовок экрана | 22px | 700 | |
| Заголовок полки | 17px | 700 | слева иконка в `--red` |
| Название на карточке карусели | 15px | 700 | |
| Название под постером | 12.5px | 500 | |
| Основной текст | 13px | 400 | `line-height: 1.55` |
| Метаданные | 11.5–12px | 400 | `--text-3` |
| Служебная подпись | 11px | 500 | `letter-spacing: .1em`, верхний регистр, `--text-4` |

Минимальный размер — 11px.

### 6.4. Два акцента и правило их разделения

Цветов-акцентов два, и они не пересекаются.

**Красный `--red`** — только действия и активные состояния: кнопка «Добавить», активная пилюля жанра, активный пункт навигации, «Продолжить», «Сбросить фильтры», рамка постера со статусом «Буду смотреть», курсор в поле ввода, активная точка карусели, иконка слева от заголовка полки, залитое сердце избранного.

**Жёлтый `--gold`** — исключительно звезда рейтинга и число рядом с ней. Больше нигде, ни при каких условиях.

Правило проверки простое: если жёлтый появился не вплотную к звезде — это ошибка. Разделение работает потому, что читатель мгновенно закрепляет за жёлтым один смысл, и оценка выхватывается взглядом без подписей.

Красным нельзя набирать абзацы текста и заголовки — только элементы управления и отметки.

### 6.5. Компоненты

**Пилюля жанра.** `padding: 7px 15px`, `--r-pill`. Неактивная — без фона, текст `--text-2`. Активная — фон `--red`, текст белый, начертание 500.

**Основная кнопка.** Фон `--red`, белый текст, `padding: 9px 18px`, `--r-pill`, 500. Наведение — `--red-hover`. Вторичная — то же на `--surface-3`.

**Селектор фильтра.** Фон `--surface`, текст `--text-2`, `padding: 7px 14px`, `--r-pill`, шеврон 13px справа. Со включённым значением — фон `--surface-3`, текст `--text`, значение в подписи: `Файл: скачан`.

**Постер.** Соотношение 2:3, `--r-xs`, подложка `--surface-2`. Пока изображения нет — иконка в `--icon-dim` по центру. Под постером название, ниже строка: год слева `--text-3`, оценка справа `--gold`.

**Карточка карусели.** Фон `--surface`, `--r-md`, `padding: 10px`. Внутри кадр 16:9 с `--r-sm`, ниже дата добавления служебной подписью, название, метаданные, строка оценки и статуса.

**Полка.** Горизонтальная прокрутка, ширина постера 104px, зазор `--gap`, правый край намеренно обрезан на половине карточки — это подсказка, что прокрутка есть.

### 6.6. Состояния

- **Наведение на постер:** `transform: scale(1.03)`, 150мс, `ease-out`. В полках у контейнера должен быть вертикальный `padding`, иначе увеличенный постер обрежется краем прокрутки.
- **Наведение на кнопку и пилюлю:** смена фона, 120мс.
- **Фокус с клавиатуры:** `outline: 2px solid var(--red); outline-offset: 2px`. Убирать `outline` запрещено, `:focus-visible` обязателен на всех интерактивных элементах.
- `@media (prefers-reduced-motion: reduce)` — все переходы и трансформации отключаются.

### 6.7. Сетка и адаптив

| Ширина | Сетка «Всё кино» | Карусель на Главной |
|---|---|---|
| ≥ 1280px | 6 колонок | 3 карточки |
| 900–1279px | 5 колонок | 3 карточки |
| 600–899px | 3 колонки | 2 карточки |
| < 600px | 2 колонки | 1 карточка, свайп |

Полки прокручиваются горизонтально на всех ширинах. На телефоне пункты навигации сворачиваются в кнопку меню, поиск и «Добавить» остаются в шапке. Минимальная поддерживаемая ширина — 360px, горизонтального скролла страницы нет нигде.

### 6.8. Иконки

Только `lucide-react`, `stroke-width: 1.5`, размер 15–20px. Залитые варианты допустимы ровно для двух: звезда рейтинга и сердце избранного. Цвет наследуется от текста, кроме перечисленного в 6.4. Эмодзи не используются.

### 6.9. Прямые запреты

- **Не копировать фирменные элементы стриминговых сервисов** — логотип, шрифт, точный оттенок их красного. Знак у проекта свой: `MOVIE_THEATRE` с подчёркиванием в акценте.
- Градиенты запрещены, с одним исключением: вертикальное затемнение поверх кадра 16:9, чтобы текст поверх него читался. Больше нигде.
- `box-shadow` и `backdrop-filter` не используются; глубина передаётся ступенями `--surface`.
- Жёлтый вне рейтинга, красный в абзацах текста.
- Готовые UI-киты (shadcn, MUI, Chakra) — дают узнаваемый шаблонный вид.
- Анимационные библиотеки; хватает `transition` и `transform`.
- Заглушки в виде цветных прямоугольников: пустой постер — это `--surface-2` с иконкой, а не случайный цвет.
- Пустые полки с текстом «здесь пока ничего нет» — такая полка просто не отображается.

## 7. План работ

Каждый этап — отдельный коммит, после третьего уже есть рабочий продукт.

**1. Каркас**
Next.js + TypeScript + Tailwind, Turso и Drizzle, схема и миграция, env-переменные (`TMDB_API_KEY`, `KINOPOISK_TOKEN`, `TURSO_URL`, `TURSO_TOKEN`, `APP_PASSWORD`), деплой пустого проекта на Vercel. Проверить, что база отвечает из серверной функции.

**2. Данные**
Клиенты TMDB и КП, логика слияния, трейлеры и продюсеры, ветка для сериалов, `POST /api/movies` и `GET /api/movies`. Проверить на сложных случаях: «Сталкер» 1979, «Аритмия» 2017, недавний зарубежный релиз, фильм без русского названия в TMDB, сериал с несколькими сезонами.

**3. Главная и каталог**
Шапка и навигация, карусель последних добавленных, полки, экран «Всё кино» с сеткой, карточка записи. Дизайн сразу по разделу 6 — не «сначала работает, потом причешем». Токены из 6.2 заводятся на первом этапе, до первого компонента.

**4. Фильтры**
Фильтрация и сортировка на клиенте, синхронизация с URL, счётчики значений, «Выбери за меня».

**5. Списки и подборки**
Ручные списки с перетаскиванием и порядком, сохранённые фильтры, экран подборок и полка списков на Главной.

**6. Поиск и статистика**
Оверлей поиска с переходом в TMDB, три пустых состояния из 5.6, экран статистики.

**7. Доводка**
Авторизация паролем, горячие клавиши, мобильная вёрстка, пустые состояния и ошибки, кнопка обновления метаданных.

**8. Эксплуатация**
Экспорт JSON, инструкция по восстановлению, README.
